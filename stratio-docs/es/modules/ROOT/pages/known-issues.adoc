= Problemas conocidos

== _Troubleshooting_ de Metabase

En caso de experimentar algún problema al usar _Stratio Discovery_, consulta la https://www.metabase.com/docs/v0.43/troubleshooting-guide/index.html[guía de _troubleshooting_ de Metabase] ^[English]^.

== Problema al especificar la clave privada para la conexión SSL con PostgreSQL®

Este es un _bug_ de Metabase que se ha resuelto en las versiones 0.42.3 y posteriores. Si tienes una versión anterior y quieres establecer una conexión SSL con PostgreSQL®, ten en cuenta que "File Path" de "SSL Client Key (PKCS-8/DER o PKCS-12)" podría no parsearse correctamente y tendrías que indicar la configuración asociada (`sslkey`) en el campo _Additional JDBC connection string options_. Esta incidencia no aplica si utilizas la base de datos _Stratio PostgreSQL Operator_.

== Cuando entro a la página principal, las exploraciones _x-ray_ no se cargan automáticamente

NOTE: Arreglado en la versión 0.50.21-0.1.X.

Este es un problema menor causado por la capa de autenticación que añade _Stratio Discovery_ a Metabase. Para representar el contenido de la página principal, se deben recuperar algunas configuraciones de usuario sobre si mostrar o no las sugerencias _x-ray_ (por ejemplo, hay muchas formas de https://www.metabase.com/docs/latest/users-guide/14-x-rays.html#disabling-x-rays[desactivar la funcionalidad de _x-ray_] ^[English]^). Lamentablemente, esta llamada a `get-properties` no está autenticada y, debido a una condición de carrera, puede ejecutarse antes de que las llamadas que establezcan una _cookie_ válida de "metabase.SESSION" tras el _login_.

Dado que se devolverán estas propiedades si y solo si el usuario es de confianza después de haber comprobado que se ha completado la autenticación, si la segunda llamada se ejecuta antes que la primera, todo funcionará correctamente, pero si es al contrario, se devolverá un valor `undefined` o vacío que no se representará en la página principal.

La solución para este problema es refrescar la página principal una vez que se ha realizado el _login_. Dado que la _cookie_ de autenticación ya se habrá escrito, a partir de entonces ya no importará el orden de ejecución.

== Aparición momentánea de la página "You are not allowed to access Metabase" en el primer acceso a _Stratio Discovery_

Este problema menor se debe a la capa de autenticación que _Stratio Discovery_ añade a Metabase. Para resolver la condición de carrera descrita en el punto anterior, se ha modificado el _endpoint_ que recupera las configuraciones de usuario para que también autentique a los usuarios y establezca la _cookie_ "metabase.SESSION".

Durante este proceso, si el usuario no existía previamente en la base de datos de Metabase, se crea automáticamente. Esto puede generar una condición de carrera en el primer acceso a la aplicación, ya que tanto el _endpoint_ de configuraciones como el de autenticación intentan crear al usuario simultáneamente, lo que a veces provoca que el _endpoint_ de autenticación falle.

Al fallar, el navegador redirige a la página de acceso no autorizado. Sin embargo, como la _cookie_ de sesión ya está establecida, la aplicación detecta que el usuario está autenticado y lo redirige de nuevo a la página principal de Metabase.

Aunque el acceso se completa sin problemas, puede aparecer momentáneamente la página de acceso no permitido; esto ocurre solo en el primer acceso a _Stratio Discovery_.

== La importación de colecciones devuelve un _timeout_

* *Causa*: la importación de colecciones grandes a veces puede devolver un error de tiempo de espera aunque la operación se haya procesado.
* *Solución*: aunque el servicio de importación devuelva este error, comprueba si la operación se ha realizado correctamente.

== Problemas de deserialización de caché

Debido a una vulnerabilidad de seguridad descubierta en una de las dependencias de Metabase, el artefacto de Metabase distribuido con _Stratio Discovery_ se compila con una versión actualizada de dicha dependencia que ya no presenta dicha vulnerabilidad.

Esto puede causar problemas en algunos casos cuando se activa la caché de Metabase, si una de las columnas de los resultados cacheados tiene un tipo cuya seguridad de deserialización no puede garantizarse por Metabase (esto ocurre, por ejemplo, con los tipos _interval_ y _json_ de PostgreSQL®).

No se devolverán errores, pero los resultados obtenidos de la caché para esta columna en particular no se podrán utilizar (contendrán un mapa con los _bytes_ no deserializados "en cuarentena"). Ten en cuenta que cualquier usuario puede activar siempre una ejecución manual de la consulta (sin usar los datos cacheados) para obtener los resultados correctos.
