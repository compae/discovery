= Crear una nueva conexión con _Stratio {modulename}_

La siguiente información explica cómo puedes conectarte a _Stratio {modulename}_ con o sin TLS. Para ello, completa los siguientes parámetros:

* *Display name*: elige un nombre para tu base de datos.
* *Host*: dirección _host_ de _Stratio {modulename}_. En un entorno de Kubernetes, el _host_ está compuesto por `${serviceName}.${Namespace}`. Por ejemplo: _virtualizer.stratio-datastore_.
* *Port*: si el servicio de _Stratio {modulename}_ se desplegó a través de _Stratio Command Center_, el puerto por defecto es el `13422`.
* *Username*: es el usuario de _Stratio {modulename}_ y su valor tiene que ser igual al parámetro `DISCOVERY_INSTANCE_NAME` en el xref:operations-guide:installing-and-upgrading/deployment.adoc[despliegue de _Stratio Discovery_].
* *Collections to sync*: permite definir las colecciones (bases de datos) que se sincronizarán desde _Stratio {modulename}_. Opciones:
** "All": sincroniza todas las colecciones disponibles en _Stratio {modulename}_.
** "Only these": sincroniza una lista específica de colecciones. Si eliges esta opción, debes escribir los nombres de las colecciones separados por comas.
** "All except": sincroniza todas las colecciones excepto las que especifiques. Si eliges esta opción, debes escribir los nombres de las colecciones separados por comas.
* *Connect with Discovery login user?*: actívalo para habilitar la suplantación de identidad.
* *Use a secure connection (SSL)?*: si habilitas esta opción la conexión se establecerá con TLS. De forma contraria, la conexión será sin TLS.
* *Additional JDBC connection string options*: lee detenidamente xref:stratio-virtualizer:user-guide:using-jdbc-odbc-drivers/jdbc.adoc#configuration-attributes[la documentación de _Stratio {modulename}_] si quieres añadir parámetros a la URL de conexión JDBC.

image::crossdata_configuration.png[]

Si sale un error "Connection refused" cuando intentas guardar la configuración, deberás revisar los valores de *Host* y *Port* y hablar con un administrador para reestablecerlos si los anteriores no funcionan. Este error aparecerá en los _logs_ cuando haya un error en la cadena de conexión JDBC:

[source,text]
----
Impossible to obtain session from server:
Tcp command [Connect(virtualizer.tmcdev-apps:8000,None,List(),Some(10 seconds),true)]
failed because of java.net.ConnectException: Connection refused
----

== Configuración de permisos de _Stratio Gosec_ para _Stratio Discovery_ sobre _Stratio {modulename}_

. Ve a _Stratio Gosec_.
. Busca en _policies_ una política existente de la instancia de _Stratio {modulename}_ a la que quieres conectarte o crea una nueva.
. Agrega el usuario de descubrimiento (nombre de usuario de la instancia de descubrimiento) a esta política.
. Guarda la política.

TIP: Para obtener más información, visita la documentación de xref:stratio-gosec:ROOT:introduction.adoc[_Stratio Gosec_].

== Suplantación de identidad en _Stratio {modulename}_

Si deseas una auditoría más detallada de quién realizó qué consulta, debes habilitar la suplantación de identidad. Para hacerlo, solo necesitas activar la opción "Connect with Discovery login user?".

image::impersonation_enabled.png[]

Ten en cuenta que, una vez que habilites la suplantación de identidad, *todas las consultas que puedes ejecutar en la interfaz gráfica de usuario ahora se ejecutarán con el usuario de inicio de sesión*. Además, *incluso si puedes navegar por la interfaz gráfica de usuario y ver las diferentes bases de datos y tablas, esto no significa que tu usuario pueda acceder a ellas*.

Si deseas asegurarte de que la suplantación de identidad esté realmente activada, puedes establecer la variable de entorno `DRIVER_LOG_LEVEL` a `DEBUG`, de modo que puedas asegurarte de que la consulta comience con `EXECUTE AS` comprobando las trazas de `stdout`.

[source,text]
----
Impersonation as user ${yourUser} for DB set to true [|false].
Current query:  {:query EXECUTE AS ${yourUser} create table default.mytest
as select id from testfra.test, ... }
----

Puedes encontrarte con errores de autenticación mientras navegas por tus datos si una política de _Stratio {modulename}_ te prohíbe ver u operar en una tabla.

image::discovery_exception.png[]

Esto significa, como muestra claramente el siguiente _log_, que no puedes acceder a esa tabla.

[source,text]
----
SQLSyntaxErrorException:
 Message: Operation not authorized
 SQLState: 42000
 Error Code: 7
----

Por favor, revisa cuidadosamente la xref:{modulenamexdata}:operations-guide:configuration/security-configuration.adoc[documentación relacionada para definir correctamente tu política de _Stratio {modulename}_], porque los problemas de autorización surgirán también en aquellas consultas que se ejecutan en la página de consulta SQL.
