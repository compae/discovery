= Configurar ACL para PostgreSQL®

_Stratio Discovery_ utiliza la base de datos de _Stratio PostgreSQL Operator_ para funcionar correctamente y requiere autorización para acceder a ella. Los permisos necesarios pueden administrarse a través de _Stratio Gosec_, el servicio proporcionado por la plataforma _Stratio Generative AI Data Fabric_ que centraliza la autorización de usuarios y servicios para diferentes bases de datos u otros servicios.

Para configurar correctamente los permisos necesarios para _Stratio Discovery_, sigue los pasos a continuación.

WARNING: Ten en cuenta que, si instalas a través de _Stratio Command Center_, estos pasos se ejecutan automáticamente.

== Crear un usuario de servicio de instancia

Para otorgar los permisos sobre los almacenes de datos necesarios para el correcto funcionamiento de la aplicación, debe existir un usuario de servicio asociado a la instancia de _Stratio Discovery_ en _Stratio Gosec_.

Si este usuario de servicio ya existe en el proveedor de identidades de la empresa (LDAP o Active Directory), debería estar incluido en _Stratio Gosec_ y no se necesita ninguna otra acción. Sin embargo, si aún no existe un usuario del servicio, debes crear uno en la aplicación _Stratio Gosec_ haciendo clic en el botón "Create user". Luego, se te pedirá el nombre, identificador y correo electrónico del nuevo usuario:

* El campo de nombre es el que se mostrará en la interfaz de _Stratio Gosec_.
* El campo ID es el más importante, ya que es el que se comparará con las credenciales de autenticación presentadas por el usuario; en el caso de _Stratio Discovery_, con el _Common Name_ del certificado TLS. Recuerda que este certificado xref:operations-guide:installing-and-upgrading/prerequisites.adoc[se almacena en Vault] y que su CN debe coincidir con la variable `DISCOVERY_INSTANCE_NAME` de la implementación.
* El campo de correo electrónico no es relevante y se puede completar con cualquier valor.

== Crear una política para acceder a _Stratio PostgreSQL Operator_

El usuario del servicio _Stratio Discovery_ debe agregarse a una política en la que se configuren los permisos para el servicio de _Stratio PostgreSQL Operator_ (la instancia de _Stratio PostgreSQL Operator_ debe ser la que tenga la URL configurada en el despliegue de _Stratio Discovery_).

Debes otorgar los siguientes permisos en los siguientes recursos (donde `+${metadataDbName}+` debe reemplazarse por el nombre de la base de datos definido durante el despliegue de _Stratio Discovery_ `MB_DB_DBNAME` en el _pod_, o en el parámetro "Database Name" en el formulario de despliegue de _Stratio Command Center_):

|===
| Tipo de recurso | Nombre | Recursivo | Comportamiento

| Domain
| `+${metadataDbName}.*+`
| false
| Usage

| Tablespace
| `+${metadataDbName}+`
| false
| Create

| Sequence
| `+${metadataDbName}.*+`
| false
| Select, Update, Usage

| Function
| `+${metadataDbName}.*+`
| false
| Execute

| Foreign Data Wrapper
| `+${metadataDbName}.*+`
| false
| Usage

| Large Object
| `+${metadataDbName}.*+`
| false
| Select, Update

| Type
| `+${metadataDbName}.*+`
| false
| Usage

| View
| `+${metadataDbName}.*+`
| false
| Select, Insert, Update, Delete, Truncate, Create, Usage

| Schema
| `+${metadataDbName}.*+`
| false
| Create, Usage

| Database
| `+${metadataDbName}+`
| false
| Create, Connect

| Table
| `+${metadataDbName}.*+`
| false
| Select, Insert, Update, Delete, Truncate, References, Trigger

| Foreign Server
| `+${metadataDbName}.*+`
| false
| Usage

| Language
| `+${metadataDbName}.*+`
| false
| Usage
|===
