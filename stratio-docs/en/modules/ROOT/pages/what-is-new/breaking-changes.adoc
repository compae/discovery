= Breaking changes

This page collects, grouped by version, the changes that affect compatibility: what stops working or changes behavior, and what action each one requires. To plan the intervention and to know when to act on each one, see the xref:operations-guide:installing-and-upgrading/upgrade-overview.adoc[upgrade planning].

[#v0564-02x]

== 0.56.4-0.2.0 (July 22, 2026)

NOTE: Since the upgrade arrives at Universe 15.1 directly from 14.10, without going through 15.0, *all* the breaking changes of version <<v0564-01x, 0.56.4-0.1.0>> apply to that route as well. Review them before upgrading, together with the xref:operations-guide:installing-and-upgrading/upgrade-overview.adoc[upgrade planning], which summarizes the impact of the intervention.

* *The secrets move to the _Stratio KEOS_ Vault injector*. Impact: the platform must be on Universe 15.1 before upgrading; the descriptor requests the new _KEOS CA secret name_ and _KEOS CA name (key inside secret)_ fields, and the keystore and truststore passwords are generated randomly on each startup, instead of being saved in Vault. Action: upgrade the platform first and review any integration that opens _/etc/pki/discovery.jks_ with a fixed password.
* *The environment variables of the probes, the resources, and the database creation stop being injected into the container*. Impact: their options remain in the descriptor and are applied to the deployment, but a process that reads them from within the container receives an empty value. Action: obtain that data from the descriptor or from the Kubernetes API.
* *The _/etc/pki/proxy.pem_ and _/etc/pki/proxy.key_ certificates stop being created*, because the container now publishes only the ones delivered to it by the Vault injector, _/etc/pki/discovery.pem_ and _/etc/pki/discovery.key_. Impact: database connections that point to those paths stop finding them. Action: repoint those connections to the new paths before upgrading.

[#v0564-01x]

== 0.56.4-0.1.0 (November 4, 2025)

This version upgrades Metabase from 0.50.21 to 0.56.4. It corresponds to Universe 15.0, which did not reach production environments, so customers receive these changes in version 0.56.4-0.2.0 of Universe 15.1.

* *The image moves to Java 21 and changes its base, its process supervisor, and its internal web server*. Impact: Java virtual machine options added by hand may no longer exist and will be ignored without warning. Action: review those options before upgrading.
* *The _Skip Metabase's Statement final cancellation in Virtualizer driver_ option is removed*, which prevented the blocking of JDBC connections with _Stratio {modulename}_ servers earlier than version 0.11.0. Impact: you have to connect to 0.11.0 or higher servers. Action: none if you come from Universes 14.8, 14.9, or 14.10, which already bring a version above that minimum; check it only if you point to a server from another deployment.
* *The Metabase Spark SQL driver stops working*: the image replaces the `hive-like` driver from which it inherits with its own version that does not include the Apache Hive™ JDBC dependency, due to vulnerabilities. The driver still loads and its databases still appear in the interface, but opening a connection fails, and the logs record "Cannot use Hive JDBC in Stratio Metabase since it has been removed due to vulnerabilities." Impact: its connections, questions, and dashboards are preserved, but they cannot be executed. The _Stratio {modulename}_ driver is not affected: it inherits from Spark SQL, but it opens its connections with the _Stratio {modulename}_ JDBC driver. Action: publish that data through _Stratio {modulename}_. Do not try to restore the original driver with the _Extra JARs to add to Metabase plugins folder_ option: it would be installed in the same directory and could break the _Stratio {modulename}_ driver, which declares it as a dependency.
* *The Amazon Athena driver is removed from the image*, since it depended on vulnerable dependencies. Impact: its connections, questions, and dashboards are preserved, but you can't execute them. Action: publish that data through _Stratio {modulename}_ or provide the driver with the _Extra JARs to add to Metabase plugins folder_ option.
* *Metabase redid its internal driver API between versions 0.51 and 0.56*. Impact: it considers any JAR file for an in-house or third-party driver that uses any of the moved namespaces, removed functionality, or changed sync signatures to be broken; databases that depend on it become inaccessible. Action: recompile it against the Metabase 0.56 API and test it with Java 21 before upgrading.
* *The audit of the content of the API responses disappears*, which recorded the body of the responses encrypted and was configured with the `LOG_ACCESS_DATA`, `DATA_AUDIT_ENCRYPTION_KEY_PASS`, `DATA_AUDIT_ENCRYPTION_IV_PASS`, `EXTRA_NGINX_LOG_PROPERTIES`, and `EMBED_TOKEN_USER_CLAIM` environment variables. Impact: the data audit lines stop being generated, without warning. Action: there is no product substitute; if your environment depended on that audit, raise the requirement before upgrading. The internal web server's access log is maintained the same way.
* *The format of the logs sent to the centralized logging platform changes*: the selector that allowed sending the messages that were already JSON in raw form depended on the Java 8 script engine. Impact: the lines still arrive, but the text escapes from the `@message` field. Action: review the parsing rules of your logging platform or of your SIEM if they depended on the previous format.
* *The "Enable OAUTH", "SSO external URI", "SSO internal URI", and "Dynamic authentication" deployment options are removed*, because authentication is fully resolved by the _Stratio KEOS_ `oauth2proxy`. Impact: the values you had configured are ignored. Action: none on the instance; review any custom automation that sets them.
* *The "OAuth2 cookie name" option is renamed to _oauth2proxy cookie name_* and the environment variable it exposes changes from `OAUTH2_COOKIE_NAME` to `JWT_COOKIE_NAME`, with the same default value. Impact: automation that reads the old name does not find the variable. Action: rename it in any automation that reads it inside the container.
* *The _Authentication method_ option moves to the advanced configuration and the `USE_GOSEC_SSO_AUTH` variable disappears*, which forced the method to `gosec-sso` and warned that it was deprecated. Impact: the variable no longer has an effect and no longer emits a warning. Action: check the authentication method in the descriptor and set it explicitly before upgrading.
* *The legacy compatibility environment variables disappear*: `TENANT_NAME` (alias of `DISCOVERY_INSTANCE_NAME`), `SECRET_NAME`, `OAUTH_COOKIE_PREFIX`, and `JWT_VALIDATION_DISABLED`, and `WGET_CUSTOM_SECURITY_OPTS` becomes `CURL_CUSTOM_SECURITY_OPTS` with a new default value. Impact: the old variables are ignored without warning, and the external JAR download options written for `wget` no longer apply. Action: replace `TENANT_NAME` with `DISCOVERY_INSTANCE_NAME` and rewrite those options in the `curl` syntax.
* *The default value of the _Middleware log level_ option changes from "DEBUG" to "INFO"*. Impact: the "DEBUG" level messages from that layer stop appearing in the logs. Action: set it again in the 'General' → 'Log levels' section if you depended on those traces.
* *The Metabase jump from 0.50.21 to 0.56.4 crosses six major versions of the product*, each with its own interface, behavior, and API changes, and some rewrite existing content during the migration. Impact: the differences are only visible after the upgrade. Action: review the https://www.metabase.com/releases[Metabase release notes] and the https://www.metabase.com/docs/latest/developers-guide/api-changelog[API changelog], and rehearse the upgrade in a preproduction environment.
* *Certain Metabase functionalities are still not compatible with the export and import of `discovery-cicd` collections*: actions, models created from CSV files, timelines, and alerts. Impact: the collection exports and imports without those elements. Action: avoid including them in collections promoted between environments, or promote them manually.
