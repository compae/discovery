= Breaking changes

This page gathers, grouped by version, the changes that affect compatibility: what stops working or changes behavior, and what action each one requires. To plan the intervention and know when to act on each one, see the xref:operations-guide:installing-and-upgrading/upgrade-overview.adoc[upgrade planning].

[#v0564-02x]

== 0.56.4-0.2.0 (July 22, 2026)

NOTE: Since the upgrade reaches Universe 15.1 directly from 14.10, without passing through 15.0, *all* the breaking changes of version <<v0564-01x,0.56.4-0.1.0>> apply to that path as well. Review them before upgrading, along with the xref:operations-guide:installing-and-upgrading/upgrade-overview.adoc[upgrade planning], which summarizes the impact of the intervention.

* *The secrets move to the Vault injector of _Stratio KEOS_*. Impact: the platform must be on Universe 15.1 before upgrading, the descriptor requests the new fields "KEOS CA secret name" and "KEOS CA name (key inside secret)", and the passwords of the key store and of the trust store are generated at random on each start-up instead of being stored in Vault. Action: upgrade the platform first and review any integration that opens _/etc/pki/discovery.jks_ with a fixed password.
* *The environment variables of the probes, of the resources, and of the database creation stop being injected into the container*. Impact: their options remain in the descriptor and are still applied to the deployment, but a process that read them from inside the container receives an empty value. Action: obtain that data from the descriptor or from the Kubernetes API.
* *The _/etc/pki/proxy.pem_ and _/etc/pki/proxy.key_ certificates stop being created*, because the container now publishes only the ones the Vault injector delivers to it, _/etc/pki/discovery.pem_ and _/etc/pki/discovery.key_. Impact: the database connections that point at those paths stop finding them. Action: repoint those connections to the new paths before upgrading.

== 0.56.4-0.1.0 (November 4, 2025)

This is the version that updates Metabase from 0.50.21 to 0.56.4. It corresponds to Universe 15.0, which did not reach production environments, so these changes reach the customers with version 0.56.4-0.2.0 of Universe 15.1.

* *The image moves to Java 21 and changes its base, its process supervisor, and its internal web server*. Impact: the Java virtual machine options added by hand may no longer exist, and they are ignored with no warning. Action: review those options before upgrading.
* *The "Skip Metabase's Statement final cancellation in Virtualizer driver" option is removed*, which prevented the blocking of the JDBC connections with _Stratio {modulename}_ servers earlier than version 0.11.0. Impact: you have to connect to servers 0.11.0 or higher. Action: none if you come from Universes 14.8, 14.9, or 14.10, which already bring a version above that minimum; check it only if you point at a server of another deployment.
* *The Spark SQL driver of Metabase stops working*: the image replaces the `hive-like` driver it inherits from with a build of its own that does not include the Apache Hive™ JDBC dependency, because of vulnerabilities. The driver still loads and its databases still appear in the interface, but opening a connection fails and the logs record "Cannot use Hive JDBC in Stratio Metabase since it has been remove due to vulnerabilities.". Impact: its connections, questions and dashboards are kept, but they cannot be run. The _Stratio {modulename}_ driver is not affected: it inherits from Spark SQL, but it opens its connections with the _Stratio {modulename}_ JDBC driver. Action: publish that data through _Stratio {modulename}_. Do not try to restore the original driver with the "Extra JARs to add to metabase plugins folder" option: it would be installed in the same directory and can break the _Stratio {modulename}_ driver too, which declares it as a dependency.
* *The Amazon Athena driver is removed from the image*, because it carried dependencies with vulnerabilities. Impact: its connections, questions, and dashboards are preserved, but they cannot be run. Action: publish that data through _Stratio {modulename}_ or provide the driver with the "Extra JARs to add to metabase plugins folder" option.
* *Metabase reworked its internal driver API between version 0.51 and 0.56*. Impact: it renders unusable any JAR file of your own or of a third-party driver that uses one of the moved namespaces, of the withdrawn features, or of the synchronization signatures that changed; the databases that depend on it become unreachable. Action: recompile it against the Metabase 0.56 API and test it with Java 21 before upgrading.
* *The audit of the content of the API responses disappears*, which logged the response body encrypted and was configured with the `LOG_ACCESS_DATA`, `DATA_AUDIT_ENCRYPTION_KEY_PASS`, `DATA_AUDIT_ENCRYPTION_IV_PASS`, `EXTRA_NGINX_LOG_PROPERTIES`, and `EMBED_TOKEN_USER_CLAIM` environment variables. Impact: the data audit lines stop being generated, with no warning. Action: there is no replacement in the product; if your environment depended on that audit, raise the requirement before upgrading. The access log of the internal web server is kept as it was.
* *The format of the logs sent to the centralized logging platform changes*: the selector that let through, verbatim, the messages that were already JSON relied on the Java 8 script engine. Impact: the lines still arrive, but with the text escaped inside the `@message` field. Action: review the parsing rules of your logging platform or your SIEM if they relied on the previous format.
* *The "Enable OAUTH", "SSO external URI", "SSO internal URI", and "Dynamic authentication" deployment options are removed*, because the authentication is resolved entirely by the `oauth2proxy` of _Stratio KEOS_. Impact: the values you had configured are ignored. Action: none on the instance; review any automation of your own that set them.
* *The "OAuth2 cookie name" option is renamed to "oauth2proxy cooke name"* and the environment variable it exposes changes from `OAUTH2_COOKIE_NAME` to `JWT_COOKIE_NAME`, with the same default value. Impact: the automation that reads the old name does not find the variable. Action: rename it in any automation that reads it inside the container.
* *The "Authentication method" option moves to the advanced configuration and the `USE_GOSEC_SSO_AUTH` variable disappears*, which forced the method to `gosec-sso` and warned that it was deprecated. Impact: the variable stops producing an effect and stops emitting a warning. Action: check the authentication method in the descriptor and set it explicitly before upgrading.
* *The legacy compatibility environment variables disappear*: `TENANT_NAME` (an alias of `DISCOVERY_INSTANCE_NAME`), `SECRET_NAME`, `OAUTH_COOKIE_PREFIX`, and `JWT_VALIDATION_DISABLED`, and `WGET_CUSTOM_SECURITY_OPTS` becomes `CURL_CUSTOM_SECURITY_OPTS` with a new default value. Impact: the old variables are ignored with no warning, and the download options for external JAR files written for `wget` stop being applied. Action: replace `TENANT_NAME` with `DISCOVERY_INSTANCE_NAME` and rewrite those options in `curl` syntax.
* *The default value of the "Middleware log level" option goes from "DEBUG" to "INFO"*. Impact: the "DEBUG" level messages of that layer stop appearing in the logs. Action: set it again in the 'General' → 'Log levels' section if you depended on those traces.
* *The jump from Metabase 0.50.21 to 0.56.4 crosses six major versions of the product*, each with its own interface, behavior, and API changes, and some of them rewrite existing content during the migration. Impact: the differences only show up once upgraded. Action: review the https://www.metabase.com/releases[Metabase release notes] and the https://www.metabase.com/docs/latest/developers-guide/api-changelog[changelog of its API], and rehearse the upgrade in a preproduction environment.
* *Certain Metabase features are still not compatible with the export and import of `discovery-cicd` collections*: actions, models created from CSV files, timelines, and alerts. Impact: the collection is exported and imported without those elements. Action: avoid them in the collections that are promoted between environments, or promote them manually.
