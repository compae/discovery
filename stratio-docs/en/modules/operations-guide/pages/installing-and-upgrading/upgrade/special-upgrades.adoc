= Special upgrades

This page preserves upgrade routes that start from _Stratio Discovery_ versions that are no longer in any maintained Universe. They are kept for very outdated installations; they are not part of the usual upgrade path.

IMPORTANT: If your instance is on a version earlier than 0.50.21-0.2.x, confirm the route with the _Stratio Discovery_ team before planning the intervention. The considerations on this page were written for the Universes of their time and may not cover everything that is needed today.

== Upgrade from Universe 12.2

Backward compatibility was broken in the Universe 12.2 descriptor because the way the host address used to access the instance is generated changed. The problem is in the registration of that host in the _Stratio Gosec_ SSO: the upgrade process does not modify it again, so you must uninstall and reinstall _Stratio Discovery_.

== Upgrade to 0.43.4-0.1.x from 0.42.x or lower

In this version, to ensure the xref:operations-guide:export-and-import-collections.adoc[export and import] of dashboard subscriptions, a Stratio migration mechanism was added on top of Metabase's internal migration. That mechanism generates two triggers in the _Stratio Discovery_ database, `stratio_insert_subscriptions` and `stratio_update_subscriptions`, which run two functions so each subscription has a unique name different from the dashboard it is associated with. Pulses, whose names can be edited, and existing promotions are unaffected, as long as the promotions have a different name from the dashboard name.

IMPORTANT: Due to a security vulnerability in the H2 drivers, version 0.43.4-0.1.0 removed the sample database, known as the "Sample Database". If that database already exists during the upgrade, delete it along with all dashboards and associated questions.

== Upgrade to 0.40.5-0.1.0 from 0.38.1-x.y.z

In this version, you can explicitly configure the behavior of the internal proxy responsible for authentication through the `OAUTH_ENABLED` environment variable. It is not mandatory: if it does not exist, the behavior is inferred from other environment variables.

NOTE: If you are upgrading from a version earlier than the xref:operations-guide:key-concepts.adoc[double version] scheme, that is, 0.40.0 or earlier, also consider the following section.

== Upgrade to 0.38.1-0.1.1 from earlier versions

This is the version in which the module's version control scheme changed: from this version on, the version consists of two parts, the first with the included Metabase version and the second with the version of the changes that Stratio adds to the Metabase core.

The most notable change is the *upgrade from Metabase 0.33.2 to 0.38.1*. Although it is a big jump, it doesn't require manual intervention to migrate data from Metabase's internal database. It also supports streaming responses, which makes the maximum row limit in previous versions unnecessary.

The module's integration with _Stratio Gosec_ SSO also changed, as explained in the xref:operations-guide:end-user-authentication.adoc[end user authentication]. The most notable point is that a double login (first with the SSO and then with an administrator email) to configure Metabase before the rest of the users can access is no longer needed: the _Stratio Gosec_ groups are automatically synchronized with the Metabase ones and a group whitelist controls who can access.

Finally, the certificate paths used to connect to the _Stratio PostgreSQL Operator_ databases via mutual TLS have changed, so you must update them in the "Additional JDBC connection string options" field of the database definition. The necessary options, with the correct paths, are as follows: `ssl=true&sslmode=verify-full&sslcert=/etc/pki/discovery.pem&sslkey=/etc/pki/discovery.pk8&sslrootcert=/etc/pki/ca-bundle.pem&prepareThreshold=0`.

This jump adds, changes, and removes several environment variables. See the xref:operations-guide:installing-and-upgrading/environment-variables.adoc[environment variables] to see which ones are current.

== Upgrade to 0.39.3 and 0.38.2 from earlier versions

Version 0.39.3 added the `PROXY_READ_TIMEOUT` environment variable for the read timeout of the internal proxy, and `STRATIO_ABSOLUTE_MAX_RESULTS` for the limit of rows delivered through the API. The second became ineffective in 0.38.1-0.1.1, with the arrival of streaming responses.

Version 0.38.2 renamed variables with hyphens, replacing them with underscores, and added component-level log options that remain current today.

In that same version, the *health check procedure* moved to being executed through `HTTP` instead of `TCP`, checking the `/api/health` endpoint on port `3009`.
