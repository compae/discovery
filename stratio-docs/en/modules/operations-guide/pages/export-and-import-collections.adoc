= Import and export collections

_Stratio Discovery_ lets you export collections, along with all their dashboards, questions, and subcollections, as JSON, which you can then import into another _Stratio Discovery_ instance, as long as both are the same version. This feature will be useful for moving collections between environments and can be easily integrated into a CI/CD tool.

WARNING: Since xref:operations-guide:installing-and-upgrading/upgrade.adoc[version 0.43.4-x.x], in the exported data of a collection, together with the dashboards, their respective https://www.metabase.com/docs/latest/dashboards/subscriptions[subscriptions] are also included. Since the import/export of data was developed to allow exchange between _Stratio Discovery_ instances of the same version in different environments, we assume each instance will have different users. Therefore, when exporting a collection, users are not saved in the subscription metadata to avoid discrepancies in the instance where the data will subsequently be imported.

[TIP]
.Difference between pulses and subscriptions
====
While pulses can be set on questions or collections, subscriptions link only to a dashboard. Subscriptions represent an evolution of pulses, which is why *it is recommended to use subscriptions and not pulses*, since https://www.metabase.com/docs/v0.40/users-guide/10-pulses#dashboard-subscriptions-will-replace-pulses-in-a-future-release[they will soon be removed as a tool in Metabase], marked as deprecated since version 0.40.
====

In promotions, SQL snippets are treated as top-level objects that do not depend on collections. Therefore, https://www.metabase.com/learn/sql-questions/sql-snippets[they must have a globally unique name].

On export, the choice is to include the SQL snippets used in the collection. Therefore, when importing that collection, only that subset of SQL snippets will be created.

NOTE: If a SQL snippet with the same name already exists, the existing one will be modified instead of creating a new one.

_Stratio Discovery_ exposes an Akka HTTP REST API based on export and import endpoints:

== Export collection

If you want to export a collection from _Stratio Discovery_, you only need to find the identifier of the collection to export:

image::identify_colection_id.png[]

Then, simply call the export endpoint and specify the collection identifier. This request must be authenticated using the _Stratio Discovery_ session identifier through the header called `x-metabase-session`.

TIP: For more information about this authorization, see the https://github.com/metabase/metabase/wiki/Using-the-REST-API[Metabase wiki].

|===
| Request type | Endpoint | Headers

| GET
| `/discovery-cicd/export/'collection_id'`
| `x-metabase-session: 'sessionId'` , `Content-Type: application/json`
|===

== Import collection

Once you have exported the collection, you only have to call the import endpoint in the target _Stratio Discovery_, indicating, as raw data, the file in JSON format that contains the exported collection. For authentication, add the _Stratio Discovery_ session identifier to the request header called `x-metabase-session`.

TIP: For more information about this authorization, see the https://github.com/metabase/metabase/wiki/Using-the-REST-API[Metabase wiki].

|===
| Request type | Endpoint | Headers

| POST
| `/discovery-cicd/import?parentId='parent_collection'`
| `x-metabase-session: 'sessionId'`, `Content-Type: application/json`
|===

As you can see, this endpoint lets you optionally specify the parent collection you want to inherit from. You can do this through the `parentId` query parameter, which must be a positive integer and refers to the collection identifier. If `parentId` is not provided, the collection will be imported as a "child" of `root`.

[IMPORTANT]
====
You cannot export:

* Any personal collection.
* A collection not previously created.
* Collections that contain dashboards that use questions that do not belong to the exported collection or to any of its subcollections.
* Collections that contain two or more questions, dashboards, or subcollections with the same name.

You cannot import:

* A collection into a target _Stratio Discovery_ that does not have the same database, field, and table names as those containing the exported questions.

In these cases, each endpoint will return the corresponding error.
====

The "FRIENDLY TABLE AND FIELD NAMES" configuration option, in the 'General' section of the Metabase administration configuration, comes disabled in _Stratio Discovery_, and there is no need to touch it: the image leaves it that way on each startup, precisely because it speeds up the export and import.

image::humanize_fields.png[]

The option is disabled in both the source and target instances, so the advantage applies to both.
