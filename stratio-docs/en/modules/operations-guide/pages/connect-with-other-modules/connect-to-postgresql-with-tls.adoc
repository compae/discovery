= Connecting to PostgreSQL® with TLS

This section provides information on the configuration needed to enable a TLS connection with a PostgreSQL® database. To do this, access _Stratio Discovery_.

== Connector for _Stratio PostgreSQL_

In addition to the standard PostgreSQL® connector included in Metabase, _Stratio Discovery_ offers the connector for _Stratio PostgreSQL_. This connector works the same way as the standard but adds the possibility of including a PostgreSQL® variable in all queries that contains the name of the logged in user who made the query, as well as other improvements.

The purpose of this variable is to filter the results according to the logged in user who runs the query because the same query can yield different results depending on the user who executes it. This can be done by creating views in the PostgreSQL® database that use this variable to filter records.

WARNING: Queries made automatically by _Stratio Discovery_, such as the ones to collect field values for use in the graphical question generator or queries to obtain pulse results, won't have any value associated with the logged in user, so they will fail when the views that use this variable are queried. For this reason we recommend that you set the scan field values option to "manual" for _Stratio PostgreSQL_ databases and don't use pulses.

WARNING: If an administrator manually activates scanning of archived values, only the values that can be seen will be stored. This can cause confusion later when other users build queries graphically with filters, since they might be offered certain values when they shouldn't or other values that should be offered might not be. We therefore recommend that you manually mark the type of columns that can be used as filters when dealing with _Stratio PostgreSQL_ databases as "search" or "text" in _Stratio Discovery_. Please note that similar issues may arise if you enable Metabase caching, as results cached for one user may be displayed to a different user.

== Configuration parameters

Fill in the following parameters as shown below:

* *Display name*: choose the name of your database.
* *Set ROLE in PostgreSQL® with the current logged user?* (_Stratio PostgreSQL_ only): uses the currently logged in user as the role to connect.
* *Set a variable containing the current logged user in all queries?* (_Stratio PostgreSQL_ only): indicates whether to set the custom variable with the logged in user in the database queries or not.
* *Name of the variable to be set with the current logged user (must contain a dot .)* (_Stratio PostgreSQL_ only): name of the PostgreSQL® variable that will contain the logged in user.
* *Host*: PostgreSQL® host address. e.g.: pg-0001.marathon.mesos.
* *Port*: PostgreSQL® port.
* *Database name*: name of the database you want to connect to.
* *Username*: same as the `DISCOVERY_INSTANCE_NAME` parameter in the xref:operations-guide:installing-and-upgrading/deployment.adoc[_Stratio Discovery_ deployment].
* *Password*: N/A.
* *Additional JDBC connection string options*: in this block, enter the appropriate value of the ``DISCOVERY_INSTANCE_NAME`` parameter in the xref:operations-guide:installing-and-upgrading/deployment.adoc[_Stratio Discovery_ deployment]. This is an example of an additional JDBC connection string that points to the correct paths for the required TLS certificates: _prepareThreshold=0&ssl=true&sslmode=verify-full&sslcert=/etc/pki/discovery.pem&sslkey=/etc/pki/discovery.pk8&sslrootcert=/etc/pki/ca-bundle.pem_.
* *Use SSL authentication*: enables SSL authentication and automatically adds certificates to the JDBC connection string, so that the path doesn't need to be explicitly indicated.

== Create a user and set permissions

Follow these steps to learn how to create a user and set permissions for a database in _Stratio PostgreSQL_:

. Go to _Stratio GoSec_.
. Find an existing policy for the _Stratio PostgreSQL_ instance you want to connect to, or create a new one.
. Add the discovery user (username of the _Stratio Discovery_ instance) to this policy.
. Save the policy.

TIP: For more information, read the xref:stratio-gosec:ROOT:introduction.adoc[_Stratio GoSec_ documentation].
