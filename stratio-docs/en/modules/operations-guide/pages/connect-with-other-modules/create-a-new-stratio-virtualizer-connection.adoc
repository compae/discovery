= Creating a new connection with _Stratio Virtualizer_

The following information explains how you can connect to _Stratio Virtualizer_ with or without TLS:

== With TLS

Fill in the following parameters:

* *Name*: choose the name of your database.
* *Host*: _Stratio Virtualizer_ host address. For example: _crossdata-1.marathon.mesos_.
* *Port*: see how xref:operations-guide:connect-with-other-modules/create-a-new-stratio-virtualizer-connection.adoc#$$_$$obtener_el_puerto_de_stratio_virtualizer[to determine the _Stratio Virtualizer_ port].
* *Database username*: same as the ``DISCOVERY_INSTANCE_NAME`` parameter in the xref:operations-guide:installing-and-upgrading/deployment.adoc[_Stratio Discovery_ deployment].
* *Connect with Discovery login user?*: click "yes" to enable impersonation.
* *Use a secure connection (SSL)?*: yes.
* *Additional parameters*: N/A.
* *Large database*: mark to minimize data synchronization.

== Determining the _Stratio Virtualizer_ port

In most cases, the port for the connection will be 8000 by default if the _Stratio Virtualizer_ service was installed using the _Stratio Command Center_. If not, you'll need to contact an administrator to tell you the port you need to use.

== Configuring _Stratio GoSec_ permission settings for _Stratio Discovery_ on _Stratio Virtualizer_

. Go to _Stratio GoSec_.
. In _policies_, look for an existing policy of the _Stratio Virtualizer_ instance you want to connect to or create a new one.
. Add the discovery user (username of the discovery instance) to this policy.
. Save the policy.

TIP: For more information, see the xref:stratio-gosec:operations-guide:stratio-gosec.adoc[_Stratio GoSec_ documentation].

== Impersonation in _Stratio Virtualizer_

If you want a more detailed audit of who made which query, you need to enable impersonation. To do this, just activate the 'Connect with Discovery login user' option.

IMPORTANT: Due to compatibility issues, this feature was disabled in all _Stratio Discovery_ versions after 0.33.x, but is now available again starting with version 0.39.1 and later.

image::impersonation_enabled.png[]

Please note that once you enable impersonation, *all of the queries you can run in the GUI will now run with the login user*. Also, *even if you can browse the graphical user interface and view the different databases and tables, this doesn't mean that your user can access them*.

If you want to make sure that impersonation is actually turned on, you can set the `DRIVER_LOG_LEVEL` environment variable to `DEBUG`, so you can make sure that the query starts with `EXECUTE AS` AS by checking the `stdout` traces.

[source,bash]
----
Impersonation as user ${yourUser} for DB set to true [|false].
Current query:  {:query EXECUTE AS ${yourUser} create table default.mytest
as select id from testfra.test, ... }
----

You might encounter authentication errors while browsing your data if a _Stratio Virtualizer_ policy prohibits you from viewing or operating in a table.

image::discovery_exception.png[]

This means, that you can't access that table, as the following log clearly shows.

[source,logs]
----
SQLSyntaxErrorException:
 Message: Operation not authorized
 SQLState: 42000
 Error Code: 7
----

Please carefully read the related xref:stratio-virtualizer:operations-guide:configuration/security-configuration.adoc[documentation to correctly define your _Stratio Virtualizer_ policy], because you will also run into authorization issues in queries that are run on the SQL query page.
