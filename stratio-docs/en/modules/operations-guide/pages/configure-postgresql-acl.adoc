= Configure ACLs for PostgreSQL®

_Stratio Discovery_ uses the _Stratio PostgreSQL Operator_ database to work correctly and requires authorization to access it. You can manage the required permissions through _Stratio Gosec_, the service provided by the _Stratio Generative AI Data Fabric_ platform that centralizes authorization for users and services across different databases and other services.

To correctly configure the permissions needed for _Stratio Discovery_, follow the steps below.

WARNING: Note that if you install through _Stratio Command Center_, these steps are executed automatically.

== Create an instance service user

To grant the permissions on the data stores necessary for the correct operation of the application, a service user associated with the _Stratio Discovery_ instance must exist in _Stratio Gosec_.

If this service user already exists in the company's identity provider (LDAP or Active Directory), include it in _Stratio Gosec_, and no other action is needed. However, if a service user does not yet exist, create one in the _Stratio Gosec_ application by clicking on the "Create user" button. Then, you will be asked for the name, identifier, and email of the new user:

* The name field is the one that will be shown in the _Stratio Gosec_ interface.
* The ID field is the most important one, since it is the one that will be compared with the authentication credentials presented by the user; in the case of _Stratio Discovery_, with the _Common Name_ of the TLS certificate. Remember that this certificate xref:operations-guide:installing-and-upgrading/prerequisites.adoc[is stored in Vault] and that its CN must match the `DISCOVERY_INSTANCE_NAME` variable of the deployment.
* The email field is not relevant and can be filled in with any value.

== Create a policy to access _Stratio PostgreSQL Operator_

The _Stratio Discovery_ service user must be added to a policy in which the permissions for the _Stratio PostgreSQL Operator_ service are configured (the _Stratio PostgreSQL Operator_ instance must be the one that has the URL configured in the _Stratio Discovery_ deployment).

You must grant the following permissions on the following resources (where `+${metadataDbName}+` must be replaced with the database name defined during the _Stratio Discovery_ deployment `MB_DB_DBNAME` in the pod, or in the "Database Name" parameter in the _Stratio Command Center_ deployment form):

|===
| Resource type | Name | Recursive | Behavior

| Domain
| `+${metadataDbName}.*+`
| false
| Usage

| Tablespace
| `+${metadataDbName}+`
| false
| Create

| Sequence
| `+${metadataDbName}.*+`
| false
| Select, Update, Usage

| Function
| `+${metadataDbName}.*+`
| false
| Execute

| Foreign Data Wrapper
| `+${metadataDbName}.*+`
| false
| Usage

| Large Object
| `+${metadataDbName}.*+`
| false
| Select, Update

| Type
| `+${metadataDbName}.*+`
| false
| Usage

| View
| `+${metadataDbName}.*+`
| false
| Select, Insert, Update, Delete, Truncate, Create, Usage

| Schema
| `+${metadataDbName}.*+`
| false
| Create, Usage

| Database
| `+${metadataDbName}+`
| false
| Create, Connect

| Table
| `+${metadataDbName}.*+`
| false
| Select, Insert, Update, Delete, Truncate, References, Trigger

| Foreign Server
| `+${metadataDbName}.*+`
| false
| Usage

| Language
| `+${metadataDbName}.*+`
| false
| Usage
|===
