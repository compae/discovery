= Configuring ACL for PostgreSQL®

_Stratio Discovery_ uses the _Stratio PostgresSQL Framework_ database to function properly and needs authorization to be able to access it. The necessary permissions are managed through _Stratio GoSec_, which is the service in the _Stratio Generative AI Data Fabric_ platform that centralizes the authorization of users and services to different databases or other services.

Follow the steps below to properly configure the necessary permissions for _Stratio Discovery_.

WARNING: Note that these steps are carried out automatically if you install using _Stratio Command Center_.

== Creating an instance service user

To grant permissions on the data stores that are needed for the application to function properly, there must be a service user associated with the _Stratio Discovery_ instance in _Stratio GoSec_.

If this service user already exists in the enterprise identity provider (LDAP or Active Directory), it should already be included in _Stratio GoSec_ and you don't need to do anything else. However, if a service user doesn't yet exist, you'll need to create one in the _Stratio GoSec_ application by clicking on the "Create user" button. You'll then be prompted for the new user's name, identifier and email address:

* The name field is what will be displayed in the _Stratio GoSec_ interface.
* The ID field is the most important because it will be compared with the authentication credentials provided by the user - in the case of _Stratio Discovery_, the _Common Name_ of the TLS certificate. Remember that this certificate xref:operations-guide:installing-and-upgrading/prerequisites.adoc[is stored in Vault] and that your CN must match the implementation's `DISCOVERY_INSTANCE_NAME` variable.
* The email field isn't relevant and you can enter any value.

== Creating a policy to access _Stratio PostgresSQL Framework_

You need to add the _Stratio Discovery_ service user to a policy where you can configure permissions for the _Stratio PostgresSQL Framework_ service (the _Stratio PostgresSQL Framework_ instance must be the one whose URL is configured in the _Stratio Discovery_ deployment).

Grant the following permissions on the following resources (replacing `+${metadataDbName} +` with the database name defined during _Stratio Discovery_ deployment `MB_DB_DBNAME` on the pod, or in the "Database Name" parameter on the _Stratio Command Center_ deployment form):

|===
| Type of resource | Name | Recursive | Behavior

| Domain
| `+${metadataDbName}.*+`
| false
| Usage

| Tablespace
| `+${metadataDbName}+`
| false
| Create

| Sequence
| `+${metadataDbName}.*+`
| false
| Select, Update, Usage

| Function
| `+${metadataDbName}.*+`
| false
| Execute

| Foreign Data Wrapper
| `+${metadataDbName}.*+`
| false
| Usage

| Large Object
| `+${metadataDbName}.*+`
| false
| Select, Update

| Type
| `+${metadataDbName}.*+`
| false
| Usage

| View
| `+${metadataDbName}.*+`
| false
| Select, Insert, Update, Delete, Truncate, Create, Usage

| Schema
| `+${metadataDbName}.*+`
| false
| Create, Usage

| Database
| `+${metadataDbName}+`
| false
| Create, Connect

| Table
| `+${metadataDbName}.*+`
| false
| Select, Insert, Update, Delete, Truncate, References, Trigger

| Foreign Server
| `+${metadataDbName}.*+`
| false
| Usage

| Language
| `+${metadataDbName}.*+`
| false
| Usage
|===
